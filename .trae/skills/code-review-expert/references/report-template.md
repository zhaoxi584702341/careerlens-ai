# references · 报告模板、分级与证据规范

> 所有审查（变更级 / 模块级 / 项目级）的报告**必须**遵循本文件的格式与规范。

---

## 一、严重程度分级（强制三分类）

| 标记 | 级别 | 判定标准 | 处理要求 |
| --- | --- | --- | --- |
| 🔴 | **必须修复** | 阻塞上线：功能性缺陷、数据不一致/丢失、安全或隐私风险、核心链路回归、契约破坏、未处理的异常导致 5xx | 上线前必须解决 |
| 🟡 | **建议优化** | 非阻塞：性能可优化、可维护性/规范问题、边界处理不完善、测试不足、日志缺失 | 建议本轮或下轮处理 |
| 🟢 | **亮点** | 值得肯定并推广的实践：清晰分层、完备降级、契约先行、良好测试与文档 | 保持并发扬 |

> 判定为 🔴 的，必须说明**具体后果**（会在什么条件下触发、影响哪条链路/哪些用户）。

---

## 二、证据规范（强制）

1. **可定位**：每个问题必须给出**具体文件路径 + 行号**，并使用可点击链接：

   `[app.ts](file:///c:/Users/admin/Desktop/boss-demo/careerlens-ai/bff/src/app.ts#L41-L52)`

   - 禁止「某处」「大概在 XX 行」「相关文件」等模糊表述。
   - 行号须为**实际存在**的行范围。

2. **给上下文**：必须附**关键代码片段**（3–10 行，标注语言），让读者不打开文件也能理解问题。

3. **给建议**：必须给出**可落地的修改建议**；能给出示例代码的尽量给。

4. **区分事实与建议**：
   - 事实：客观缺陷/可复现错误（用陈述句）。
   - 建议：主观优化/风格偏好（用「建议……」）。
   - 二者不得混写。

5. **不确定即标注**：证据不足或需运行验证的，标注「**待确认**」并写明需要补充的信息（如「需确认上游是否恒定返回该字段」）。

6. **不泄密**：报告中**禁止**出现密钥、Token、密码、连接串、`.env` 内容、真实用户数据。发现敏感信息时，只报告「存在未脱敏凭据，位置 X」，**不回显具体值**。

## 四、单项问题书写示例

> 🔴 **降级路径缺失，LLM 失败会导致整条链路 5xx**
> - **位置**：[main.py](file:///c:/Users/admin/Desktop/boss-demo/careerlens-ai/python-service/main.py#L210-L226)
> - **事实**：`/api/analyze` 在 LLM 调用异常时直接向上抛出，未返回规则层结果，且响应中缺少 `meta.degraded`。
> - **后果**：LLM 不可用时前端收到 500，四个接口联动失败，「规则降级」能力失效。
> - **建议**：捕获 LLM 异常后返回 HTTP 200 + 规则层结果，并置 `meta.degraded=true`、`meta.aiMode="rule"`。示例：
>   ```python
>   try:
>       ...
>   except Exception:
>       return build_rule_response(degraded=True)
>   ```

> 🟡 **建议：`window` 事件监听未成对移除**
> - **位置**：[RadarView.vue](file:///c:/Users/admin/Desktop/boss-demo/careerlens-ai/frontend/src/views/RadarView.vue#L119-L131)
> - **事实**：`handleResize` 在提交成功后注册，但未在 `onBeforeUnmount` 中移除。
> - **建议**：将注册与移除成对管理，或在卸载时统一 `removeEventListener`。

> 🟢 **亮点：统一响应契约 + 跨标签页状态同步**
> - **位置**：[jobDescription.ts](file:///c:/Users/admin/Desktop/boss-demo/careerlens-ai/frontend/src/stores/jobDescription.ts)
> - 说明：store 采用「单一数据源 + localStorage 持久化 + 跨标签页同步 + 静默降级」范式，与既有 resume store 同构，边界处理完善。

## 五、自检清单（提交报告前逐条确认）

- [ ] 每个问题都有**文件行号链接**与关键代码片段
- [ ] 每个问题都有**可落地建议**
- [ ] 事实与建议已分开陈述
- [ ] 不确定项已标注「待确认」

- [ ] 已明确审查范围与基准，未把历史遗留归为本次变更
- [ ] 若涉及核心链路/契约，已给出回归风险结论
- [ ] 全量审查时，五个维度均有覆盖（无内容的维度写「无」）
