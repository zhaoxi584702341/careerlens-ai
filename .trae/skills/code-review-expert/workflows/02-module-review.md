# 02 · 模块级审查工作流（指定目录 / 服务 / 文件）

> 适用：用户点名某一模块，如「审查 `bff/`」「看看 `python-service/main.py`」「review 前端 stores」。
> 前置：**必须先执行** `workflows/00-preflight.md`（Step A 判定粒度=模块级并确认路径，Step B 加载上下文，Step C 读取完整上下文）。

---

## 目标

在**用户指定的边界内**做完整、深入的审查，覆盖指定维度（默认全量五维度），并评估该模块与相邻层的耦合与契约一致性。

---

## 执行步骤

### 1. 确认模块边界

- 明确用户点名的**确切路径**；若只说「某模块」而未给路径 → 先澄清，**不得自行扩大范围**。
- 边界 = 目标路径内的全部源码 + 其**直接依赖/被依赖的相邻文件**（用于判断调用是否正确）。

### 2. 建立模块地图

| 动作 | 命令/工具 | 目的 |
| --- | --- | --- |
| 列出模块文件 | `Glob`（如 `bff/src/**/*.ts`） | 掌握全貌，避免遗漏 |
| 找入口 | 读取该层入口文件 | 确定执行主链 |
| 找导出/公共 API | `Grep` 检索 `export` / `public` / `def ` / `@RestController` | 界定对外契约面 |
| 找调用方 | `Grep` 全仓检索该模块导出符号 | 评估改动的影响半径 |

### 3. 分层检查（按模块所属层套用）

- **前端 `frontend/`**：组件职责、状态管理范式（见 `SKILL.md`（§七 项目专属审查要点））、`api/*.ts` 请求封装与类型、响应式与生命周期、错误提示与降级展示。
- **BFF `bff/`**：路由定义、入参校验、`callJava` 转发契约、`meta` 组装（`withBffMeta`）、SQLite 持久化、异常返回结构。
- **Java `java-service/`**：Controller/DTO/异常处理分层、字段名映射（驼峰↔蛇形）、RestTemplate 超时与异常传播、`@Valid` 校验。
- **Python `python-service/`**：FastAPI 路由与模型、`rules.py` 规则引擎正确性、`AI_MODE` 三档位行为、LLM 失败降级路径、契约字段产出。
- **契约 `contracts/`**：OpenAPI 与实际实现一致性、Schema 必填项、错误码表完整性。

### 4. 五维度逐项检查

按 `references/dimensions.md` 完整过一遍（维度范围以 Step A 为准，默认全量）。

### 5. 跨层一致性核对（强制）

- 该模块暴露/消费的字段名、错误码、`meta` 结构，是否与相邻层一致。
- 若涉及共享契约，核对 `contracts/openapi.yaml` 是否同步。
- 若涉及前端共享状态，核对是否存在**多份本地状态**（本地 `ref` 与全局 store 并存）。

---

## 输出

严格按 `references/report-template.md` 输出。模块级报告**必须包含**：

1. **审查范围**：模块路径 + 文件清单 + 该模块职责一句话概括。
2. **模块地图**：入口 / 公共 API / 被谁调用（简述）。
3. **按五维度**（或指定维度）分组的问题清单（🔴/🟡/🟢 + 文件行号链接 + 修改建议）。
4. **跨层一致性结论**：与相邻层/契约是否一致；如不一致，指明是哪一侧需改。
5. **模块健康度小结**：主要风险与改进优先级。
