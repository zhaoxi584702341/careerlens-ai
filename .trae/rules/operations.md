# 操作准则（Operations Rules）

本文件固化 CareerLens AI 项目后续**内容修改**类操作的行为准则，所有后续改动必须遵循。

## 1. 默认不触碰进程

- 进行内容修改（代码、样式、文案、配置外的资源文件等）时，**只修改文件本身**。
- **不额外开启、重复开启任何服务或进程**；已运行的服务继续复用。
- 不因“修改内容”而主动启动新的前端 / BFF / Java / Python 实例。

## 2. 前端改动复用热更新

- 前端为 Vite dev（支持 HMR）。前端**纯代码改动由热更新自动生效**，无需关闭或重启任何进程。
- 仅在热更新失效或明确需要重建时，才按第 3 条执行“先关后开”。

## 3. 确需改配置/状态时，严格“先关后开”

当修改必须让进程重启才能生效时（如改配置、改环境变量、安装/升级依赖、调整启动参数）：

1. **先完全关闭**对应进程，并确认端口 / 进程已释放（端口不再处于 Listen 状态、进程已退出）。
2. **再启动**单个干净实例。
3. 逐个服务按依赖顺序启动，确认每层启动成功后再进入下一层。

## 4. 禁止的反模式

- ❌ **未关闭就直接重启**（同一服务上叠加新实例）。
- ❌ **重复开启**（同一服务并存多个实例，例如多个 `tsx watch` 残留）。
- ❌ 在“仅内容修改”场景下无谓地关闭 / 重启服务。

## 5. 服务与端口对照

| 端口 | 服务 | 启动目录 | 启动命令 |
| --- | --- | --- | --- |
| 8000 | Python FastAPI | `python-service` | `.venv\Scripts\python.exe -m uvicorn main:app --host 127.0.0.1 --port 8000` |
| 8080 | Java Spring Boot | `java-service` | `mvn -B --no-transfer-progress spring-boot:run` |
| 3000 | BFF (Node/tsx) | `bff` | `npm run dev` |
| 5173 | 前端 Vite dev | `frontend` | `npm run dev` |

启动顺序：Python → Java → BFF → 前端。关闭时反向进行。

## 6. 校验原则

- 变更后按需验证，但验证**不得引入重复进程**。
- 涉及接口链路时，以一次端到端请求确认为准，不反复重启服务来试错。
